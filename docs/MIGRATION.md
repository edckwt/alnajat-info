# هجرة موقع النجاة إلى Laravel

كل المراحل منفذة: القاعدة، لوحة التحكم، الموقع العام، النشرة PDF. النشر على الخادم في [DEPLOY.md](DEPLOY.md).

## التشغيل المحلي (MAMP)

```bash
cd /Applications/MAMP/htdocs/alnajat-laravel

# 1) القاعدة القديمة info يجب أن تحتوي آخر نسخة من الموقع:
/Applications/MAMP/Library/bin/mysql80/bin/mysql -uroot -proot info < ../alnajatinfo/anajat_news.sql
#    (مسار mysql يختلف حسب نسخة MAMP؛ phpMyAdmin يؤدي الغرض نفسه)

# 2) جداول القاعدة الجديدة
php artisan migrate

# 3) نقل البيانات ثم التحقق
php artisan legacy:import --fresh
php artisan legacy:verify

# 4) ملفات الموقع القديم: css، js، images → public/، والخطوط → resources/fonts،
#    والصور upload → storage/app/public/upload (ويُنشأ public/storage)
php artisan alnajat:assets          # روابط رمزية (محلياً)، أو --copy على الخادم

# 5) الاختبارات
php artisan test

# 6) التشغيل
php artisan serve        # الموقع http://localhost:8000 واللوحة http://localhost:8000/cp
```

الدخول بنفس اسم المستخدم (أو البريد) وكلمة المرور الحالية. أول دخول يرقّي الهاش من MD5 إلى bcrypt.

## ما الذي يفعله legacy:import

| القديم | الجديد | ملاحظة |
| --- | --- | --- |
| users | users | الهاش القديم في `legacy_password`، و`password` فارغ حتى أول دخول |
| category | categories | |
| newspaper | newspapers | رابط الشعار يصبح نسبياً |
| banners | banners | |
| news | news | نص الخبر يُنقل كما هو حرفياً؛ الصورة تصبح `upload/...` |
| news_meta (category_id) | category_news | الروابط لأقسام أو أخبار محذوفة تُتخطى وتظهر في التقرير |
| publications | publications | `pdf_version` يُحسب من رقم النشرة كما في `pdfVersion()` |
| setting | settings + home_boxes | مفاتيح `box_*_N` و`pdf_box_*_N` تصبح 30 صفاً في `home_boxes` |
| upload | uploads | |

- المعرّفات (id) كلها محفوظة.
- الأمر قابل للتكرار، ويكتب تقريراً في `storage/app/private/legacy/`.
- `legacy:verify` يقارن الجهتين صفاً بصف ويفشل عند أي فرق.

## وحدات اللوحة

| الوحدة | الرابط | ملاحظات |
| --- | --- | --- |
| الدخول | `/cp/login` | باسم المستخدم أو البريد، وكلمات المرور القديمة تعمل |
| الأخبار | `/cp/news` | 5 أنواع (خبر، صوتي، مرئي، تغريدة، مشروع)، بحث وتصفية، نسخة مطابقة، إخفاء/نشر، حذف |
| ترتيب أخبار اليوم | `/cp/news/order` | سحب وإفلات، يحفظ `sort_order` تصاعدياً |
| النشرات | `/cp/publications` | تاريخ فريد لكل نشرة، غلاف، ملف PDF بديل، رابط معاينة الـ PDF |
| الأقسام، الصحف، الإعلانات | `/cp/categories` … | تفعيل/تعطيل بنقرة |
| الملفات | `/cp/uploads` | رفع عدة ملفات دفعة واحدة |
| الأعضاء | `/cp/users` | دور لكل عضو + صلاحيات إضافية له؛ لا يستطيع تعطيل أو حذف نفسه |
| الملف الشخصي | `/cp/profile` | لكل عضو: بياناته وصورته (سحب وإفلات) وجواله ونبذة، وتغيير كلمة المرور بالحالية، والجلسات النشطة. الترحيل `000800` يضيف avatar/phone/bio |
| الأدوار والصلاحيات | `/cp/roles` | مصفوفة صلاحيات لكل وحدة وإجراء؛ «مدير» و«محرر» أدوار نظام |
| قوالب النشرة | `/cp/pdf-templates` | مصمم بالسحب والإفلات: غلاف، صفحة قسم متكررة، ختام؛ مسودة ← اعتماد ← افتراضي |
| الإعدادات | `/cp/settings` | عام، إغلاق الموقع، أكواد الهيدر/الفوتر، الـ PDF، صناديق الرئيسية والنشرة |
| روابط مفقودة | `/cp/missing-links` | للمدير: كل رابط أعاد 404 مع عدد مرات طلبه ومصدره، للمتابعة بعد الانتقال |

- كل رفع ملفات بالسحب والإفلات (أو اللصق، أو النقر) مع معاينة قبل الحفظ: مكوّن `<x-admin.dropzone>`.
- حفظ خبر بتاريخ جديد يُنشئ نشرة ذلك اليوم تلقائياً، كما كان `publications_create` يفعل.
- الصور تُحفظ في `storage/app/public/upload` (تُعرض من `/storage/upload/…`) بنفس الأسماء والمصغّرات القديمة (`thumbs/{name}_{w}x{h}`، `{name}_thumbnail`). القيم في القاعدة تبقى `upload/…` كما في الموقع القديم، والتحويل كله في `App\Support\Media`، والروابط القديمة `/upload/…` تُحوَّل (301). النقل: `php artisan alnajat:move-uploads` (انظر DEPLOY.md).
- المحرر TinyMCE 7 (رخصة GPL) من jsDelivr، بواجهة عربية.

## الموقع العام

نفس قوالب الموقع القديم (Bootstrap 4 و`css/style.css`) ونفس الروابط:
`/`، `?all`، `?date=Y-m-d`، `show/{id}`، `category/{id}`، `search/{كلمة}`، `publication/{id}`، `archive.html`.
روابط `index.php?action=…` القديمة تُحوَّل 301 إلى الروابط النظيفة. إعداد «إغلاق الموقع» يعرض السبب للزوار فقط.

## الصلاحيات

- القائمة الكاملة في `config/permissions.php` بصيغة `وحدة.إجراء` (مثل `news.publish`، `settings.pdf`)، وكل مسار في `routes/admin.php` محمي بـ `can:`.
- صلاحيات العضو = صلاحيات دوره + صلاحياته الإضافية. من يمنح الصلاحيات لا يمنح إلا ما يملكه، ولا يعدّل مديراً إلا مدير.
- بدون `news.manage_all` يعدّل المحرر ويحذف وينشر أخباره فقط. بدون `وحدة.publish` يُحفظ السجل مخفياً.
- الترحيل `000600` ينشئ جدول `roles` ويبقي عمود `users.role` كما هو، فالأعضاء الحاليون لا يتأثرون.

## قوالب النشرة المصمَّمة

- التصميم JSON بالمليمتر (`App\Support\PdfDesign`)، يُرسم في mPDF بعناصر `position: fixed` وخلفيات `@page` مسمّاة.
- المتغيرات: `{{date_long}}`، `{{date_hijri}}`، `{{category_name}}`، `{{page}}`، `{{pages}}`، `{{archive_url}}`… (القائمة في المحرر).
- القالب المعتمد لا يُعدَّل (حتى لا تتغير النشرات القديمة)، بل يُنسخ. الافتراضي يُسند تلقائياً للنشرات الجديدة؛ وبدونه تبقى القوالب القديمة v1..v5.
- عنصر QR يحتاج `composer require mpdf/qrcode`؛ بدونه يُطبع الرابط نصاً.

## واجهات الموقع

- «الكلاسيكية» = قوالب `resources/views/site` كما هي (الموقع القديم). «الجديدة» في `resources/views/themes/modern` وملفاتها الثابتة في `public/themes/modern` (CSS وJS بلا أدوات بناء).
- الاختيار من الإعدادات ← إعدادات عامة ← «واجهة الموقع». الرجوع للقديمة في أي وقت بنفس المكان.
- المعاينة قبل الاعتماد (لمن يملك `settings.general` فقط): `/?theme=modern`، وتبقى في جلسته مع شريط «إنهاء المعاينة»؛ الزوار لا يتأثرون.
- أي ملف غير موجود في مجلد الواجهة يُؤخذ من الكلاسيكية؛ فلإضافة واجهة ثالثة: مجلد جديد + مفتاحه في `App\Support\Theme::THEMES`.
- أغلفة النشرات في الواجهة الجديدة تُرسم من قالب كل نشرة (المصمَّم أو القديم vN) بتاريخها، فتطابق ملف الـ PDF.

## النشرة PDF

| الرابط | المحتوى |
| --- | --- |
| `today-news.html` | آخر نشرة منشورة |
| `pdf-publication/{id}` | نشرة معيّنة (بقالبها المصمَّم، أو قالب نسختها pdf-v1..v5) |
| `pdf-show/{id}` | خبر واحد |

- يُعرض في المتصفح، و`?download=1` للتنزيل.
- التوليد مرة واحدة ثم يُخدم الملف من `storage/app/pdf`. تعديل خبر أو ترتيب يوم يُسقط نشرة ذلك اليوم فقط؛ تعديل الإعدادات أو الصناديق أو الأقسام أو الصحف أو الإعلانات يُسقط الكل. نشرة اليوم تُحدَّث كل 15 دقيقة كحد أقصى.
- `php artisan pdf:warm --limit=30` يجهّز آخر النشرات مسبقاً.

### فروق مقصودة عن النظام القديم

- «إخفاء من الـ PDF» يُحترم الآن في النشرة (الاستعلام القديم كان يتجاهله).
- صورة «اقرأ من المصدر» البيضاء (غير معرّفة في القديم فكانت تظهر نص خطأ) صارت `source-white-ar.png`.
- `pdf-publication/{id}` يعيد ملف الـ PDF فعلاً (القديم كان يعيد صفحة النشرة).

## أدوات الفحص قبل الإطلاق

| الأمر | ماذا يفحص |
| --- | --- |
| `legacy:verify` | كل صف منقول مطابق للقديم |
| `alnajat:check-links {الموقع}` | عينة 200 رابط قديم: 200 أو 301 إلى صفحة 200 |
| `pdf:samples --old={الموقع القديم}` | نشرة من كل نسخة قالب من النظامين للمطابقة البصرية |
| `php artisan test` | يشمل: الرئيسية بـ 15 صندوقاً بأقل من 15 استعلاماً |

## التراجع

`php artisan legacy:export-since "وقت الانتقال" --deletes` يصدّر كل ما تغيّر في النظام الجديد بصيغة القاعدة القديمة. التفاصيل في [DEPLOY.md](DEPLOY.md#9-التراجع).

## CSS لوحة التحكم

`public/admin/css/app.css` مبني من قالب روبيك ويحتوي فقط الأصناف المستخدمة في قوالب اللوحة. عند إضافة أصناف Tailwind جديدة:

```bash
cd resources/admin && npm install && npm run build
```

(منفصل عن `package.json` الرئيسي لأن روبيك على Tailwind 3 وLaravel 13 على Tailwind 4.)
